# CW-M5-011 — Category Membership Indexing

## Classification

`CATEGORY_MEMBERSHIP_SOURCE_ONLY_VERIFIED`

The source-side category contract is implemented and tested. Durable category
storage, category-member queries, and category-page MVC integration remain
blocked because the repository has no native category persistence model or
authorized category database slice.

## Existing architecture audit

The imported MediaWiki renderer already recognizes `[[Category:Title]]` and
returns typed per-render metadata. It runs after the revision-aware template
expander, so categories emitted by successfully reached templates are visible
in the result. Directives are not emitted as article-link content.

The existing application persistence contains `Page`, `PageRevision`,
`PageTag`, `PageReference`, processing-instruction, token, and attachment
tables. `PageTag` is the existing user/tag feature; it does not represent the
MediaWiki Category namespace, sort keys, source revisions, or incomplete
expansion state. No `Category` or page-category relationship table, category
repository, or category-specific provider-neutral contract exists.

`TagsController` and its view provide tag browsing only. There is no category
page route, category view, category pagination contract, or category-specific
authorization query. Reusing tags or the tag route would change the existing
domain semantics and could disclose pages without a category visibility
policy.

## Typed directive contract

`MediaWikiCategory` retains source category title and offset, normalized title,
canonical `Category::title` navigation produced by the existing
`TwNamespaceNavigation` rules, optional sort key, source page/revision/import
provenance, and the `Membership` directive classification.

The parser distinguishes membership directives from leading-colon explicit
links. Invalid category identities produce `InvalidCategoryTitle` and are not
eligible metadata. Repeated directives are deduplicated by canonical category
navigation plus ordinal sort key; the same category may therefore retain
distinct explicitly supplied sort keys while exact repeats collapse.

## Source-only indexing boundary

`MediaWikiCategoryIndexPlanner.Build` creates an immutable
`MediaWikiCategoryIndexPlan` from a render result. It performs no database
write and has no repository dependency. The plan contains canonical category
memberships, source revision provenance, deterministic ordering, and blocking
diagnostic codes.

The plan is replaceable only when source page/revision/title provenance is
complete and no expansion, dependency, unsupported-runtime, or resource-limit
diagnostic makes the category set incomplete. Otherwise it sets
`PreserveExistingMembership=true`; callers must retain the last verified
membership rather than destructively replacing it with a partial result.

This gives future page-save/import integration an explicit boundary:
authoritative content is rendered and planned during the authorized mutation
workflow, then a category store may replace memberships in that workflow's
transaction. Reading or rendering a current or historical revision does not
invoke that boundary.

## Transclusion and completeness

Directives in expanded Wikitext and directives reached through resolved nested
templates are represented in the result. Supported conditional expansion
contributes only the selected branch. The current result does not attribute a
directive to a particular template body after expansion, so it does not claim
complete direct-versus-transcluded historical attribution.

Missing, restricted, ambiguous, unavailable, recursive, unsupported, rejected
Lua, and expansion-budget conditions make the plan incomplete. Categories
generated by unavailable Lua or unsupported extensions are not invented. An
incomplete plan preserves existing membership.

## Security and invariants

- Rendering remains read-only.
- Historical rendering cannot update current membership.
- Incomplete expansion cannot erase a verified index.
- Category membership is not treated as page-read authorization.
- No unbounded category query, Lua activation, Cargo activation, production
  database access, worker change, or migration-planner change was introduced.
- Existing renderer input/output, expansion, cancellation, and diagnostic
  budgets remain unchanged.
