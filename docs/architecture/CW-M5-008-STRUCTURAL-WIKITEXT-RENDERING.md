# CW-M5-008 Structural Wikitext and HTML rendering compatibility

## Scope and classification

`STRUCTURAL_WIKITEXT_RENDERING_PARTIALLY_VERIFIED`.

The existing renderer was audited and one reproducible structural defect was
corrected: mixed list markers such as `*#` were rendered as unordered nested
lists, and definition-list markers were treated as paragraph text. The
documented subset below is deterministic, bounded, and sanitized; it is not a
claim of complete MediaWiki HTML parity.

## Existing architecture and precedence

`MediaWikiWikitextRenderer` first expands imported Wikitext through the
bounded `MediaWikiTemplateExpander`, then parses the expanded text into a
typed document AST. The block parser recognizes redirects, tables, galleries,
typed infobox tokens, headings, horizontal rules, lists, definition lists,
and paragraphs in that order. Inline parsing then handles links, media,
categories, references, emphasis, TemplateStyles, static Mermaid output, and
explicitly unsupported constructs.

Template-generated block markup is therefore parsed by the same block AST as
source markup. No second renderer or Markdown parser was introduced.

## Supported subset

| Area | Classification | Behavior |
| --- | --- | --- |
| Headings | `VERIFIED_CORRECT` | Matching `=` delimiters at levels 1–6 render as safe `<h1>`–`<h6>` elements with inline parsing. Malformed or mismatched delimiters remain paragraph text. |
| Unordered lists | `VERIFIED_CORRECT` | `*` runs become balanced `<ul>/<li>` trees, bounded by the existing parse-depth and block limits. |
| Ordered lists | `VERIFIED_CORRECT` | `#` runs become balanced `<ol>/<li>` trees. |
| Mixed/nested lists | `VERIFIED_CORRECT` | The confirmed marker-selection defect is fixed: the marker at each nesting level controls that level, so `*#` creates an ordered child under an unordered parent and transitions remain balanced. |
| Definition lists | `VERIFIED_CORRECT` | The confirmed paragraph-classification defect is fixed: `; term` and `: definition` lines form bounded `<dl><dt>/<dd>` output. More advanced same-line definition syntax remains outside this subset. |
| Tables | `VERIFIED_CORRECT` | `{|`, `|-`, `!`, `|`, `|+`, and `|}` produce typed `<table>`, `<caption>`, `<tr>`, `<th>`, and `<td>` structures, including supported nested tables. |
| Table attributes | `VERIFIED_CORRECT` | Only allow-listed class, id, role, scope, ARIA label, and bounded spans are emitted. Styles, event handlers, unsafe URLs, unsupported attributes, and excessive values are rejected or ignored. |
| Internal links | `VERIFIED_CORRECT` | Imported page resolution, piped labels, category collection, and supported file/image mapping retain the existing repository and URL policy. |
| External links | `VERIFIED_CORRECT` | Existing HTTP/HTTPS validation and encoded link text remain in force; unsafe schemes are neutralized. |
| Bold/italic | `VERIFIED_CORRECT` | Supported apostrophe delimiters produce balanced `<strong>`/`<em>` nodes, including combined bold-italic nesting. |
| Paragraph boundaries | `VERIFIED_CORRECT` | Blank lines and structural blocks flush paragraphs; block elements are not inserted into paragraph wrappers. |
| Template-expanded structures | `VERIFIED_CORRECT` | Expansion completes before structural parsing, so a template-produced table/list enters the same bounded AST pipeline. |

Heading IDs are not generated by this renderer, preserving the existing
anchor/link identity rather than introducing a competing scheme. Complex
MediaWiki list continuation, full definition-list grammar, table layout
features outside the typed attribute allow-list, and complete file/category
semantics remain unsupported or only partially represented.

## Security and bounds

The existing limits remain unchanged: input and output size, block count,
parse depth, table nesting, rows, cells, cell characters, attributes,
diagnostics, media dimensions, and cancellation. List nesting is clamped by
the existing parse-depth boundary. No unbounded structural recursion was
introduced.

All text and link labels are HTML-encoded. Raw table attributes are never
copied into HTML. Inline CSS remains rejected; TemplateStyles continues to
use its separate sanitizer and signed, permission-checked delivery path.
Lua and Cargo remain disabled/rejecting by default, and historical source
resolution is unchanged.

## Corrected defect and regression evidence

`TryParseListItem` now uses the marker at the current nesting level rather
than the first marker for the item type. The list renderer groups adjacent
items by their current ordered/unordered kind, preserving valid parent-child
relationships. A typed definition-list block was added to keep `;` and `:`
content out of ordinary paragraphs.

The focused regression
`RendersMixedListsAndDefinitionListsWithBalancedStructure` proves balanced
mixed list HTML and `<dl>` output. Existing tests cover headings, ordinary
lists, tables, captions, spans, nested tables, links, media, emphasis,
sanitization, TemplateStyles, infoboxes, Mermaid fallback, expansion, and
resource limits.

## Limitations and independent gates

This milestone uses synthetic renderer evidence only. It does not establish
exact MediaWiki 1.45 HTML, historical reference parity, real Cargo/Lua
behavior, host worker certification, production authorization certification,
or migration readiness. No production database, MediaWiki service, worker
configuration, or authenticated evidence was modified.
